# RuleQuant 公式结果统计与可视化设计

## 背景

RuleQuant 现有九个一级功能，其中“一键算公式”可以展示某一期每条公式的独立输出，但缺少把全部公式输出按属性汇总的视图。用户需要快速回答两类问题：

1. 某一计算期里，每个生肖、尾数等结果分别被多少条公式排除或支持；
2. 最近十个计算期里，这些结果累计出现多少次，以及每一期的分布如何。

本功能固定命名为“公式结果统计”。它不是新的预测算法，不计算正确率，也不改变综合参考权重；它只对现有公式引擎已经产生的结果做等权计数。

## 目标

- 在现有侧边栏增加第十个一级入口“公式结果统计”。
- 统计最新计算期和最近十个计算期内所有启用公式的输出。
- 排除类与支持类完全分开，所有公式每次贡献均为 1，不使用成功率、权重或人工确认状态加权。
- 覆盖生肖、尾数、头数、合数、段位、五行、波色、半头、半波、门数、自定义号码等现有公式类型；按用户要求不统计单双和大小。
- 增加可视化二级窗口，在不离开页面的情况下查看排行、期次变化和公式来源明细。
- 桌面与手机均具备完整功能，并延续现有 iOS 26 玻璃材质、圆角、动效和交互语言。
- 跟随现有开奖同步链路每日实时更新，不建立容易过期的独立统计副本。

## 非目标

- 不新增或修改预测公式。
- 不判断公式本期是否正确，不显示成功率排名。
- 不把排除次数与支持次数相减或混合成一个分数。
- 不统计 `kill_parity`、`include_parity`、`kill_size`、`include_size`，这些公式仍保留在其他现有功能中。
- 不新增服务端统计接口、数据库表或定时任务。
- 不引入新的重量级图表运行时。
- 本阶段不发布到 GitHub；只有用户明确说“发布”后才执行推送或部署。

## 统计口径

### 计算期与对应期

每个统计快照以“计算期”为主键：使用该期开奖号码运行全部启用公式，输出用于对应下一期开奖。

- 最新输出：使用当前最新开奖作为计算期，对应期显示“下期待开奖”。
- 最近十期：取最近十个计算期的公式输出；已经存在下一期开奖的记录显示实际对应期号，最新一期仍显示“下期待开奖”。
- UI 同时展示“计算期”和“对应期”，避免把公式输入期与验证期混淆。

### 等权计数

- 一条公式输出一个目标，该目标次数加 1。
- 一条公式输出多个目标，每个不同目标各加 1。
- 同一条公式的同一期输出若出现重复目标，先去重，避免重复累计。
- 不读取回测成功率、近期连对、信号权重或 `participatesInReference`。
- 只统计 `enabled = true` 的公式；计算失败的公式进入“跳过公式”计数和明细，不阻断整个页面。

### 动作分组

排除类（展示“被排除次数”）：

- 杀一肖、杀波色、杀一合、杀一尾、杀一头、杀半头、杀半波、杀一门、杀五行、杀一段；
- “杀三肖当九肖”的三肖部分作为排除生肖单独统计。

支持类（展示“被支持次数”）：

- 选生肖、参考波色、七尾、六肖、八肖、八肖管两期、九肖；
- “杀三肖当九肖”的九肖部分作为支持生肖单独统计。

### 语义目标

- 普通公式按 `mappedResult` 统计。
- 杀半头、杀半波、杀一门优先统计 `secondaryMappedResult` 中的语义标签（例如“0头单”“红波双”“1门”），明细中仍展示实际受影响号码。
- 杀三肖当九肖同时产生两条贡献：`secondaryMappedResult` 的排除三肖与 `mappedResult` 的支持九肖。
- 自定义集合按支持号码统计。

## 数据流与每日更新

功能直接消费 `RuleQuantTerminal` 已经合并完成的 `activeDraws`、当前 `rules` 和 `config`：

1. 现有网站同步、静态共享数据或人工录入更新开奖；
2. Zustand/Dexie 状态更新 `activeDraws`；
3. 统计组件的 memo key 随开奖、规则或配置变化；
4. 最近十期结果自动重新计算并刷新视图。

因此它天然继承当前自动同步与每日更新能力。统计结果只作为可重建的内存派生数据存在，不另存数据库，不会发生主数据已更新而统计仍过期的情况。离线时保留最后一次已加载数据并显示数据来源与最新计算期。

## 架构

### 纯统计模块

新增 `src/lib/formula-summary/formula-summary.ts`，负责：

- 排序开奖；
- 对最近最多十个计算期调用现有 `calculateRule`；
- 把公式类别转换为动作、目标类型和语义目标；
- 生成每期贡献、分组排行、十期累计和跳过项；
- 提供稳定、可测试、与 React 无关的数据结构。

建议的核心结构：

- `FormulaSummaryContribution`：计算期、对应期、公式、动作、目标类型、目标、公式过程与受影响号码；
- `FormulaSummaryPeriod`：某一计算期的所有贡献、分组和跳过公式；
- `FormulaSummaryGroup`：动作 + 目标类型下按次数降序排列的目标行；
- `FormulaSummaryReport`：最新期、最近十期、启用公式数、贡献总数和可用分组。

### 页面组件

新增 `src/components/formula-result-statistics-view.tsx`，只接收 `draws`、`rules`、`config`：

- 页面状态：最新/近十期、排除/支持、目标类型、选中目标、可视化窗口开关；
- 用 `useMemo` 构建报告；
- 统计条与明细使用语义 HTML 和原生 CSS；
- 弹窗用 portal 挂载到 `document.body`，支持 Escape、遮罩关闭、焦点恢复和滚动锁定。

路由新增 `/formula-result-statistics`，主终端的 `ViewKey`、导航项和标题映射同步增加该视图。

## 主页面信息架构

### 第一层：范围与状态

- 标题：`公式结果统计`
- 说明：`按最新一期或最近十期，统计每条启用公式产生的排除与支持次数。`
- 数据状态：最新计算期、对应期、启用公式数、统计期数、跳过公式数。
- 范围切换：`最新输出` / `最近十期`
- 动作切换：`排除统计` / `支持统计`

### 第二层：类别与排行

- 类别使用可横向滚动的分段按钮，名称直接对应业务语义，例如生肖、尾数、半波、门数。
- 主证据使用按次数降序的横向条形排行；左侧是目标名称，右侧始终显示精确次数。
- 前 5—6 项默认可见，全部项目保持可滚动/展开，避免把长尾压成难读的饼图。
- 每一行都可以打开对应目标的可视化二级窗口。

### 第三层：公式来源

- 页面下方显示当前选中目标的公式来源列表。
- 每条包含公式名、计算期、对应期、计算表达式/过程摘要与输出。
- 手机端使用单列 disclosure；桌面端使用对齐列表，不依赖宽表格。

## 可视化二级窗口

### 容器行为

- 桌面：居中大号玻璃弹窗，最大宽度约 1120px，背景页面保留但不可滚动。
- 手机：从底部进入并占据安全区域内的近全屏抽屉，顶部固定拖拽柄、标题和关闭按钮。
- 打开后默认聚焦标题/关闭按钮；Escape、遮罩、关闭按钮均可退出，退出后焦点回到触发项。

### 可视内容

1. 当前类别完整排行：横向排序条形图，条形从零开始，精确值直标，不使用图例。
2. 最近十期变化：期次 × 目标的紧凑矩阵/微型条形视图；每格同时有数字或可读文本，颜色只增强强弱而不作为唯一编码。
3. 选中目标明细：列出贡献它的公式，点击可展开计算过程。

最近十期恰好提供足够的 8—10 个时间点，因此可以展示小型趋势；数据不足 4 期时自动降级为离散期次条形/精确列表，不画容易误导的折线。

## 图表合同

### 分析问题

哪些目标在当前计算期或最近十期被最多公式排除/支持，贡献来自哪些公式？

### 核心结论形态

用户首先看到排序后的次数差异，随后按需查看期次变化和公式证据；不输出预测结论。

### 图表家族

- 主视图：比较/排行 → 排序横向条形图；
- 二级期次视图：时间变化/矩阵 → 10 期紧凑矩阵或小型多序列条形；
- 精确查找：公式明细列表。

### 编码与色彩

- 排除使用现有 rose 语义根色，支持使用现有 cyan/blue 语义根色；同一图只使用一个非中性色根及其明暗变化。
- 选中态使用描边、背景与图标三重编码，不依赖颜色。
- 所有条形从零开始，值直接标注；没有冗余图例、渐变图形填充或装饰性网格。

### 数据充分性与降级

- 类别少于 4 个目标：改用精确值列表/KPI，不勉强画图。
- 时间少于 4 期：改用分期离散条形或列表。
- 无贡献：显示原因明确的空状态，保留筛选控件。

## 响应式与可访问性

- 桌面与手机为同等功能状态，不把手机端简化成只读摘要。
- 触控目标最小 44px；横向类别筛选可触摸滚动且不遮挡证据。
- 手机主页面单列，排行标签与精确次数始终可见；不依赖 hover。
- 弹窗使用 `role="dialog"`、`aria-modal="true"`、可读标题和关闭说明。
- 条形图同时提供文本标签、数值和可访问描述。
- 遵循 `prefers-reduced-motion` 与 `prefers-reduced-transparency`。
- 适配底部导航和 `safe-area-inset-bottom`，不出现内容被浮动导航遮挡。

## 视觉系统

沿用项目当前样式，不创建另一套设计语言：

- 页面内容使用现有可读的实色内容面板；筛选器、浮层和导航使用 iOS 26 玻璃材质。
- 复用现有背景、文本、边框、强调色、圆角、阴影和 motion token。
- 二级窗口的玻璃只用于容器和工具条，图表证据区保持足够不透明度以确保文字与条形清晰。
- Lucide 图标继续使用现有 1.5—2px 线性风格；“公式结果统计”使用数据汇总/图表语义图标。
- 桌面侧边栏允许导航区域独立滚动，避免第十项在较矮屏幕被裁切。
- 商业级完成度来自精确对齐、信息层级、触控反馈、焦点管理、空态/错误态和响应式细节，不堆叠与业务无关的发光、粒子或大屏装饰。
- 转场使用接近 iOS 的短时弹性曲线；窗口打开、筛选切换、选中目标和关闭均有一致的位移/缩放反馈，并对减少动态设置提供无动画降级。

## 性能预算

- 计算规模约为 `最近 10 期 × 约 112 条启用公式 ≈ 1,120 次`，复用公式引擎已有缓存。
- 报告只在开奖、公式或配置改变时重算；普通筛选和打开弹窗只筛选已生成报告。
- 二级窗口只渲染当前动作/类别，避免一次挂载全部图表。
- 使用 CSS/SVG/DOM 原生图形，不新增图表依赖；不使用常驻动画。
- 目标：统计构建在常规桌面设备上保持瞬时感，移动端交互不产生明显卡顿；若实际测量超预算，再把报告构建移入 Web Worker，而不是提前增加复杂度。

## GitHub 开源参考的原则转化

- Grafana：借鉴“总览面板 → 保留筛选上下文的 drill-down → 公式证据”的阅读路径，不引入其监控平台复杂度。
- Tremor：借鉴紧凑 KPI、排序排行和清晰数据密度，不照搬其组件外观。
- visx：借鉴低层、按需、可定制的思想；本功能规模更小，直接使用原生条形与布局即可。
- Recharts：项目已有依赖，但当前图形简单且性能/包体优先，因此只在原生实现不足时作为后备，不主动增加客户端图表开销。

参考只用于交互与信息设计原则；页面的布局、色彩、字体和组件继续以 RuleQuant 现有 UI 为唯一视觉基准。

## 测试与验收

### 单元测试

- 最新期与最近十期的计算期/对应期对齐；
- 只统计启用公式；
- 每条公式每个唯一目标只加 1；
- 排除与支持不混合；
- 杀三肖当九肖同时生成排除三肖与支持九肖；
- 半头、半波、门数使用语义标签；
- 公式错误被记录并跳过；
- 数据不足、空数据、非数字期号排序。

### 集成与静态检查

- 路由、导航、页面标题与手机“更多”入口存在；
- TypeScript、ESLint、Vitest、生产构建通过；
- 前端主要页面和新页面 HTTP 200；
- 后端 `/api/cloud/state` 继续正常响应或按本地配置明确降级。

### 浏览器验收

- 桌面：主排行、动作/范围/类别筛选、打开/关闭二级窗口、公式明细；
- 手机：底部导航进入、单列排行、全屏抽屉、安全区域、触摸滚动；
- 浅色/深色、减少动态、窄屏和较矮桌面；
- 侧边栏十项无裁切，无横向溢出，无内容被底部导航遮挡。

## 已确认决策

用户已确认名称为“公式结果统计”，要求增加商业级、完善而美观的可视化二级窗口，桌面和手机端都完成，严格延续现有 iOS 26 交互，每天随现有数据实时更新，不统计单双与大小，并要求在不持续停下来询问的情况下继续实现。上述设计按这些明确要求执行。
